個人計畫書：路線情報員

你的定位：你是整個專案的路線情報員。全台灣雙鐵與國內線班表、離島海象潮汐、小琉球與綠島的民營交通船資料、加上政府官方連假行事曆——這些決定「行程排得成不成立」的真實世界情報，全都由你負責打通並整理成穩定可靠的資料流。

一、你的專屬主場與工作減壓設計

  • 你掌控的目錄：services/、data/
  • 依賴鎖定原則：專案核心套件（leaflet、react-leaflet、zod 等）已由架構師預裝鎖定，非架構師分支禁止改動根目錄 package.json 與 package-lock.json。
  • 這次特別幫你卸下重擔的調整：
    • 先前我們發現一個人手寫 5 區共 60–75 筆精選景點太操勞了。現在改成你寫一支腳本先從 TDX 觀光 V2.1 撈出 5 區的初稿骨架，接著全隊 4 個人各自認領 1–2 區填「公休日、室內雨備、無障礙與避雷提醒」，你只需人工精修自己認領的 1 區（例如澎湖）就好！
    • 只要守住 schema/trip.ts 定義的輸出格式，Proxy 怎麼寫、KV 怎麼設定過期時間、船班備援怎麼排版，完全由你做主。

二、你真正要動腦的地方（AI 不能替你決定）

  1. 破解 TDX 免費「5 次／分鐘」限流陷阱：

TDX 免費一般會員全帳號每分鐘只能打 5 次 API（取 Token 限 20 次/分），而且 Cloudflare Worker 的記憶體變數不會跨機房共享。你必須想清楚「哪些資料交給 GitHub Actions 每天慢慢抓好存成靜態 JSON（間隔 ≥ 15 秒才不會 429）」，「哪些資料放進 Cloudflare KV 讓全台灣所有使用者共用同一份快取」。

  1. 訂定台灣各海域合理的海象燈號門檻：

東北季風下的「基隆–馬祖」跟「東港–小琉球」耐浪程度完全不同。你需要參考航港局與實際經驗，決定浪高幾公尺或風力幾級才轉黃燈／紅燈，既能保命又不至於晴天也誤報停航。

  1. 民營離島船班的更新與免責提醒：

小琉球、綠島、蘭嶼的假日機動加班船常常不在 TDX 裡。你要決定 ferry-fallback.json 怎麼附上最直達的船公司公告頁或航港局即時連結，讓旅客出門前點一下就能複查。

四、你的工作節奏與自我檢查清單

  1. 前置準備：註冊 TDX 與氣象署免費開發者帳號；建立 Cloudflare Worker ＋ 綁定一個 KV Namespace；從 main 開出個人分支 feat/route-intel-pipeline（禁止在 main 直接開發）。
  2. 搭建 GitHub Actions 慢速靜態同步（services/scripts/）：
    • 寫腳本每日定時抓雙鐵時刻骨架、國內航空季班表、TDX 觀光 V2.1 合法旅宿與長尾景點、以及政府行政機關辦公日曆表。
    • 強制加上請求間隔（sleep >= 15000ms）與 429 指數退避重試，確保免費帳號天天穩穩同步不中斷。
    • 順手把 5 區（澎湖、小琉球、北北基、台南、花東）從 TDX 觀光 V2.1 抓出初稿骨架放到 data/curated/drafts/，發給全隊 4 人各自認領校對後彙整進 data/curated/。
  3. 搭建 Cloudflare Worker ＋ KV 快取代理（services/proxy-worker/）：
    • 提供 /api/weather（3 小時 KV 快取）、/api/marine（15 分鐘 KV 快取）、/api/air（15 分鐘 KV 快取）、/api/rail-live（10 分鐘 KV 快取），Token 獨立存 KV（4–6 小時）。
  4. 補齊離島民營船表與優惠規則檔（data/）：
    • 整理 data/ferry-fallback.json（含小琉球東琉線、綠島、蘭嶼、澎湖重要航線與官網查驗連結）及 data/promotions.json。
  5. 封裝主機雙任務與 Zod 安全降級（services/ai-client/）：
    • 封裝 parseNaturalQuery() 與 fetchAiSummary()：一旦主機離線、逾時（10 秒）、收到 429，或 回傳 JSON 沒通過 Zod 驗證，立刻平順回傳降級結果讓純規則引擎接手。
  6. 本機檢查再發 PR：
    • 執行 npm run typecheck 與 npx vitest run services/ 確保全綠燈。
    • 以 git diff --stat origin/main 確認未變動 schema/ 或 package.json。
    • 使用 /backup 或標準 Git 流程發起 Pull Request，禁止直推 main。

五、直接貼給路線情報員 AI 的執行指令

可直接複製給 AI 的執行指令
你是我的協作 AI，負責「路線情報員（外部資料與 API 管線）」開發工作。請先閱讀專案根目錄的 AGENTS.md 與 .agents/skills/tw-trip-contract/SKILL.md，並嚴格遵守以下規範：

1. 【目錄、合約與依賴邊界】
   - 只在 services/ 與 data/ 目錄內建立與修改檔案，絕對不要更動 schema/、engine/、src/ 或根目錄 package.json。
   - 所有輸出資料必須嚴格 import 並符合 schema/trip.ts 定義的型別（包含 CuratedSpot, TransportLeg, SeaRiskLevel）。
   - 禁止在 main 分支直接 commit，所有更動必須在 feat/route-intel-<主題> 分支完成並透過 PR 提交。

2. 【破解 TDX 5 次/分限流：GitHub Actions 慢速預抓 (services/scripts/)】
   - 撰寫 sync-tdx-static.ts 與 sync-holidays.ts：
     (a) 每次呼叫 TDX API 之間必須強制等待至少 15 秒（>= 15000ms），遇到 HTTP 429 需自動退避重試，以符合 TDX 免費會員 5 次/分鐘限制。
     (b) 將雙鐵常用班表骨架、國內線定期班表、TDX Tourism V2.1 合法旅宿與延伸景點同步至 data/static/。
     (c) 另寫一個腳本將首批 5 區（penghu, xiaoliuqiu, taipei, tainan, hualien_taitung）觀光 V2.1 資料轉成帶有空白 closedDays / isIndoor / tips 欄位的初稿 JSON（data/curated/），方便團隊 4 人分區校對。
     (d) 同步台灣政府行政機關辦公日曆表至 data/holidays.json。

3. 【Cloudflare Worker + KV 共用快取 (services/proxy-worker/)】
   - 使用 Cloudflare KV Binding 實現跨節點共用快取，禁止只用記憶體變數快取 Token。
   - TDX OAuth 2.0 Access Token 存入 KV 快取 4 小時。
   - 實作端點與對應 KV TTL：/api/weather (3 小時，整合 CWA 鄉鎮預報 + 潮汐 F-A0021-001 + 波浪 F-A0020-001 並轉換成 SeaRiskLevel)、/api/marine (15 分鐘)、/api/air (15 分鐘)、/api/rail-live (10 分鐘)。
   - CORS 僅允許指定的 GitHub Pages 網域，所有金鑰由 Worker Secrets 讀取。

4. 【離島船班備援與優惠清單 (data/)】
   - 建立 data/ferry-fallback.json（涵蓋小琉球東琉線、綠島、蘭嶼、澎湖等表定班次、全半票價與官網確認 sourceUrl）。
   - 建立 data/promotions.json 記錄 Taiwan PASS、TPASS 與可配置之國旅補助規則骨架。

5. 【主機雙任務呼叫與 Zod 降級保護 (services/ai-client/)】
   - 封裝 parseNaturalQuery(text, timeoutMs = 10000) 與 fetchAiSummary(result, timeoutMs = 10000)。
   - 收到回傳後必須先跑 Zod Schema 驗證；只要逾時、斷線、HTTP 429 或 Zod 驗證失敗，立刻安全捕捉並回傳 { status: 'fallback', reason }。

6. 【自我檢查測試】
   - 使用 Vitest（並以 @cloudflare/vitest-pool-workers 或 mock KV/fetch）測試：TDX 429 退避、KV 快取命中不重複打 TDX、CWA 波浪轉 SeaRiskLevel 門檻、以及 AI 逾時/Zod 失敗自動降級。全部測試通過後再收尾。
