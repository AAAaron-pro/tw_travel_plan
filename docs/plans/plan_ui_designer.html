個人計畫書：介面設計師

你的定位：你是整個專案的介面設計師。旅客打開網頁的第一眼會不會想繼續點、同團算完分帳看不看得懂、在太陽很大或訊號很差的海邊手機好不好點——決定我們能不能真正贏過「去趣」和「Funliday」的臨門一腳，就在你手上。

一、你的專屬主場與創作自由

  • 你掌控的目錄：src/
  • 完全不用等別人就能動工：專案一建好，你就直接拿 schema/mockTripData.ts 裡完整的兩組假資料開發所有畫面與互動；等路線情報員跟優惠精算師合併後，只要把呼叫函式換上真實引擎就能立刻連通。
  • 順手幫全隊減壓的認領項：等路線情報員從 TDX 產出 5 區初稿後，你認領 1 區（例如台南） 校對景點真實公休與備註。

二、你真正要動腦的地方（AI 不能替你決定）

  1. 高資訊密度的「克制感」（我們最大的勝出點）：

升級後結果頁同時要顯示「主機白話導讀」、「全團省多少＋改平日建議」、「每人分帳 AA 明細」、「國土測繪中心互動地圖」、「每日時間軸＋按鈕微調」、「外帶匯出」。如果全部攤平塞在一頁，就會重蹈去趣介面雜亂的覆轍。你要自己設計資訊分層：第一眼只露「總價／省下金額／今日地圖與骨架」，分帳明細、官網查驗連結與細部花費收進乾淨的展開抽屜或分頁。

  1. 「點兩下就能微調」的手機順手度：

我們刻意放棄容易跟手機上下滑動打架的手指跨天拖拉，改用 44px 按鈕微調（換順路點／上移／下移／刪掉／切雨備）。你要設計出點完按鈕後視覺焦點不跳走、金額變化有清楚微回饋的手感。

  1. 手機、iPad 與桌機的雙欄比例：

在 iPad 橫向（>= 1024px）左邊時間軸＋右邊國土測繪中心地圖並列極好用；但在手機或 iPad 直向，地圖如果固定佔半個螢幕會完全壓縮閱讀區，建議改為「頂部切換按鈕（列表 / 地圖）或可收合小地圖」。

四、你的工作節奏與自我檢查清單

  1. 前置準備：從 main 開出個人分支 feat/ui-warm-tactile，建好 src/styles/tokens.css 與雙欄／手機自適應外殼（App Shell）。
  2. 打造 3 步驟精簡調查表（1-to-3 焦點原則）：
    • 頂部可選「一句話讓主機幫我填」：接到主機回傳的 missingFields 時只高亮提醒缺的那 1–2 題；若收到降級訊號（離線或排隊滿），用溫和口語提示「目前直接點下面表單也很快」，不跳錯誤警告視窗。
    • Step 1：出發地（origin）＋ 目的地（本島／離島）＋ 日期天數（自動提示早鳥窗）＋ 預算與住宿等級／間數。
    • Step 2：同團混搭身分加減計數器（+ / - 至少 44px）＋ 已持有卡片（TPASS / 敬老愛心卡 / 離島住民）。
    • Step 3：交通方式複選 ＋ 行程節奏（慢活／剛剛好／跑滿／幫我決定）。
  3. 打造結果與互動微調頁：
    • 摘要與省錢區：主機 150 字白話導讀（有才顯示）、全團原價 vs. 折後價、「改平日可省更多」提示條、以及可展開的「各身分每人分帳 AA 表」。
    • 雙模式地圖 ＋ 時間軸：國土測繪中心 WMTS＋Leaflet 每日編號路線圖（桌機／平板橫向並列，手機一鍵切換列表/地圖）；每個景點旁附 44px 按鈕微調列（換順路備選／上移／下移／刪除），海象黃紅燈時秀出「一鍵切換雨備」開關。
    • 免登入外帶工具列：一鍵開每日 Google Maps 導航路線、下載 .ics 行事曆檔、列印專用樣式、Firestore 唯讀分享短連結（含「複製為我的副本來改」模式）。
  4. 自我確認再發 PR：跑完元件互動測試、用瀏覽器實測手機 375px 與 iPad 768px/1024px 佈局、執行 npm run build 零錯誤後發 Pull Request。

五、直接貼給介面設計師 AI 的執行指令

可直接複製給 AI 的執行指令
你是我的協作 AI，負責「介面設計師（前端架構與設計工程）」開發工作。開工前必須先閱讀並嚴格遵守專案根目錄的 AGENTS.md 與 .agents/skills/tw-trip-contract/SKILL.md（可同時參考 vercel-react-best-practices 與 web-design-guidelines 原則）。請協助我完成以下實作：

1. 【目錄隔離與 Mock 先行】
   - 只在 src/ 目錄內建立與修改檔案，絕對不要修改 schema/、services/ 或 engine/。
   - 開發初期直接 import schema/trip.ts 與 schema/mockTripData.ts 的完整 TripPlanResult 假資料實作全部互動（預留呼叫 engine/mutations 的 callback 介面）。

2. 【Warm Tactile 設計系統與反 AI Slop 鐵律】
   - 建立 src/styles/tokens.css：--bg-canvas: #f4f4f0、--bg-surface: #ffffff、--border-subtle: #e2e1db、--accent-primary: #d97706、--text-primary: #1c1917、--text-secondary: #57534e。
   - 嚴禁暗底紫藍漸層、嚴禁 Box-in-Box 巢狀圓角卡片（改用單層平面＋留白＋1px 細線分隔）、嚴禁使用任何原始 Emoji 當圖示（一律使用 lucide-react，strokeWidth={1.5}）。
   - 所有金額、票價、車次時刻、分帳與天數一律啟用 `font-variant-numeric: tabular-nums`。
   - 所有互動元件具備 8 態回饋（含 :focus-visible 外框與 active:scale-[0.97]，過渡 < 200ms）。

3. 【平板與手機觸控規格】
   - 所有按鈕、身分加減計數器與微調控制最小點擊熱區 44px × 44px，相鄰間距 >= 8px，不依賴 :hover 顯示關鍵操作。
   - 版面高度採 min-height: 100dvh 並於底部保留 env(safe-area-inset-bottom)。
   - 平板橫向 (>= 1024px) 採左時間軸＋右地圖雙欄；手機與直向平板提供清楚的「列表 / 地圖」切換，避免地圖擠壓表單與文字。

4. 【完整頁面與台灣口語文案】
   - 3 步驟精簡調查表：含出發地、目的地（本島/離島）、住宿等級與間數、同團混搭身分計數器、交通複選與節奏；頂部選配「一句話讓主機幫我填」（能處理 missingFields 高亮補填，並在降級時溫和引導改用表單）。
   - 結果儀表板：
     (a) 選配的 150 字主機白話導讀（僅在 aiSummary 存在時顯示）。
     (b) 預算總覽卡：原價 vs. 折後省下金額、「改平日省更多」提示條、以及可展開的「各身分每人 AA 分帳明細表」。
     (c) 零元台灣地圖（使用 react-leaflet + 內政部國土測繪中心 WMTS EMAP 圖磚，標記每日景點編號與路線折線，需採動態載入避免阻塞首屏）。
     (d) 時間軸與 44px 按鈕微調列：支援「換順路點 / 上移 / 下移 / 刪除」與海象黃紅燈時「一鍵切雨備」，不做易誤觸的手指跨天拖拉。
     (e) 外帶功能列：每日 Google Maps 多點路線按鈕、下載 .ics 行事曆按鈕、@media print 潔淨列印樣式、PWA 離線儲存（localStorage）與 Firestore 免登入唯讀分享（含旅伴一鍵複製副本微調）。
   - 全面檢查文案，確保自然台灣日常口語，完全不含翻譯腔與網路黑話。

5. 【自我檢查測試】
   - 使用 Vitest + Testing Library 測試：加減同團身分人數與修改出發地更新狀態、降級訊號下仍可完整送出、單點替換與切雨備按鈕事件正確觸發、AA 分帳抽屜可正常展開。執行 `npm test` 與 `npm run build` 確保 0 錯誤。
