個人計畫書：優惠精算師

你的定位：你是整個專案的優惠精算師。台灣交通優惠多、週五六與連假房價落差大、一家老小出門更常碰到「誰該出多少錢」與「星期幾休息別白跑」的問題——整套產品真正讓旅客覺得比去趣、Funliday 聰明的邏輯大腦，全在你這條產線上。

一、你的專屬主場與邊界

  • 你掌控的目錄：engine/
  • 依賴鎖定原則：專案核心套件（leaflet、react-leaflet、zod 等）已由架構師預裝鎖定，非架構師分支禁止改動根目錄 package.json 與 package-lock.json。
  • 完全獨立的作業環境：所有運算都是純 TypeScript 函式（輸入資料 $\rightarrow$ 輸出完整 TripPlanResult），完全不需要碰網頁 CSS、也不用自己寫網路連線程式。
  • 順手幫全隊減壓的認領項：等路線情報員從 TDX 產出 5 區景點初稿後，你認領 1–2 區（例如小琉球＋花東），幫這些點補上準確的公休日、室內雨備與長輩推車友善標籤。

二、你真正要動腦的地方（AI 不能替你決定）

  1. 多重優惠「互斥與配對」的決策樹：

高鐵大學生 5 折跟早鳥 65 折不能併用、愛心票「每組限 1 位必要陪伴者」半價、Taiwan PASS 臺鐵版要玩滿幾天／跨幾段才比單買早鳥划算——這些商業邏輯必須由你設計清楚的優先順序，讓系統幫旅客挑「真正最省的那組」並講出白話理由。

  1. 平假日／連假住宿係數與「改平日提醒」門檻：

結合 data/holidays.json，週五、週六與連假房價通常比平日貴不少。你要拿捏各住宿等級（budget / standard / premium）的合理倍率，以及「大概省超過多少錢（例如每人省 NT$ 600 以上）才主動跳出建議改期提示」，才不會一點點差價也一直吵使用者。

  1. 離島與多代同遊的「人性化緩衝」：

帶著 65 歲以上長輩或未滿 3 歲幼兒時，不僅要自動切保守步調（每日 ≤ 3–4 點、優先選汽車／台灣好行而非全島騎機車），在離島最後一天的回程搭船／搭機前一定要預留充足緩衝，絕不能把緊鄰碼頭關門前的時間排滿景點。

  1. 使用者按「換一個景點」時的即時重算邏輯：

介面設計師會有換點、調順序、切雨備的按鈕，你要寫出乾淨的純函式，讓畫面一按就能秒重算門到門時間、預算差額與公休日衝突。

四、你的工作節奏與自我檢查清單

  1. 前置準備：從 main 開出個人分支 feat/fare-engine-core（禁止在 main 直接開發），對照 schema/trip.ts 讀懂新的 TripInput（含 origin、lodgingTier）與 TripPlanResult。
  2. 升級優惠與分帳引擎（engine/pricing.ts）：
    • 依 origin 自動對應最近高鐵／台鐵樞紐站及合理離島機場／港口。
    • 實作高鐵（5–28 天早鳥、大學生、敬老 5 折、愛心 1+1 半價）、台鐵、離島（居民 7 折、離島回程機票免營業稅、客輪 3–12 歲半價／未滿 3 歲 1 成保險票）與 Taiwan PASS / TPASS 比價。
    • 新增 住宿平假日與連假估算（吃 data/holidays.json），算出 weekdayShiftSavingHint（例：「若往前 1 天週四出發，全團住宿估計可省 NT$ 2,400」）。
    • 新增 同團各身分個別分帳 perIdentitySplit（交通依身分各自計價、住宿依房間數均攤、租車／共同門票平分）。
  3. 升級分段排程與按鈕微調函式（engine/planner.ts & engine/mutations.ts）：
    • 依 TripInput 組出每日 DayPlan，強制加上車站／機場／港口門到門緩衝時間。
    • 實作 3 個給前端按鈕呼叫的純函式：replaceStopWithNearbyBackup()（換一個同區順路未重複且沒公休的點）、reorderDayStops()（上下調順序後重算時間與 Google Maps 路線 URL）、toggleRainBackup()（遇黃紅燈或點切換時替換為 isIndoor: true 備案）。
  4. 品質抓錯與外帶輸出產生器（engine/reviewer.ts & engine/exporters.ts）：
    • reviewer.ts：自動檢查每日星期與 closedDays 衝突、前後站轉乘過緊、超預算與海象風險警告。
    • exporters.ts：產生每日 Google Maps 多點導航連結（https://www.google.com/maps/dir/...）與標準 RFC 5545 .ics 行事曆字串（純文字產生，零瀏覽器依賴）。
  5. 本機檢查再發 PR：
    • 跑通所有邊界測試（至少 10 個），執行 npx vitest run engine/ 與 npm run typecheck 確保 100% 通過。
    • 以 git diff --stat origin/main 確認未變動 schema/ 或 package.json。
    • 使用 /backup 或標準 Git 流程發起 Pull Request，禁止直推 main。

五、直接貼給優惠精算師 AI 的執行指令

可直接複製給 AI 的執行指令
你是我的協作 AI，負責「優惠精算師（台灣優惠規則、AA 分帳與排程引擎）」開發工作。請先閱讀專案根目錄的 AGENTS.md、.agents/skills/tw-trip-contract/SKILL.md，並參考 docs/reference/trip-go.md 與 trip-review.md 內的抓錯思路。嚴格遵守以下規範：

1. 【目錄、純函式與依賴紀律】
   - 只在 engine/ 目錄內建立與修改檔案，絕對不要修改 schema/、services/、src/ 或根目錄 package.json。
   - engine/ 內所有函式必須為純函式（Pure Functions），嚴禁直接呼叫 fetch()、localStorage 或操作 DOM；景點清單、假日表、海象與票價皆透過參數傳入。
   - 輸入與輸出嚴格符合 schema/trip.ts 的 TripInput 與 TripPlanResult。
   - 禁止在 main 分支直接 commit，所有更動必須在 feat/fare-engine-<主題> 分支完成並透過 PR 提交。

2. 【出發地、同團優惠、住宿係數與 AA 分帳 (engine/pricing.ts)】
   - 依 TripInput.origin 自動對應最近雙鐵站與往返離島的合理港口/機場組合。
   - 實作同團混合身分交通計價：高鐵早鳥窗（5–28天）、大學生優惠、65歲敬老5折、愛心票（每組限本人+1位陪伴者半價）、離島設籍居民約7折、離島回程機票免營業稅、客輪 3–12 歲半價與未滿 3 歲 1 成保險票；並與 Taiwan PASS / TPASS 比價擇優推薦。
   - group 的每個欄位都是人頭數：disabled（身障本人）與 disabledCompanion（必要陪伴者，不可多於 disabled）分開計價；offshoreResidentCount 是設籍離島的人數，只有這幾位適用居民票價。
   - 結合傳入的政府辦公日曆表（holidays.json），依 lodgingTier 與 roomCount 計算平日 vs 週五六/連假住宿費；若週五六/連假佔比高，估算「往前或往後挪一天改平日出發」的 weekdayShiftSavingHint。
   - 產出完整的 BudgetBreakdown，包含各身分別每人應付分帳明細 perIdentitySplit（交通依身分實付、住宿與租車依成人/佔床人數均攤）。所有金額都是整數新台幣，除不盡的差額填進 roundingRemainderTwd，必須滿足 Σ(count × totalPerPersonTwd) + roundingRemainderTwd = discountedTotalTwd。

3. 【分段排程與按鈕微調純函式 (engine/planner.ts & engine/mutations.ts)】
   - 組合每日 DayPlan（含門到門時間緩衝：雙鐵+20分、國內機/離島船+45分）；weekday 必須等於 date 的星期（0＝週日），交通段出發／抵達時間一律 HH:MM。
   - 若含 senior65Plus > 0 或 infantUnder3 > 0，切換友善步調（每日 <= 3–4 個點、避開全島機車、優先挑選 wheelchairAndStrollerFriendly: true）。
   - 實作三個純函式供前端單點微調並回傳更新後的 TripPlanResult：
     (a) replaceStopWithNearbyBackup(plan, dayIndex, stopId, candidateSpots)
     (b) reorderDayStops(plan, dayIndex, fromIndex, toIndex)
     (c) toggleRainBackup(plan, dayIndex, useBackup)

4. 【自動抓錯與外帶匯出 (engine/reviewer.ts & engine/exporters.ts)】
   - reviewer.ts：檢查星期與 closedDays 衝突、轉乘緩衝不足、預算超標（isOverBudget）與海象警示，輸出 ReviewWarning[]。
   - exporters.ts：為每日生成 Google Maps 多點路線連結 googleMapsRouteUrl，並實作 generateIcsCalendar(plan: TripPlanResult): string（標準 .ics 格式純文字）。

5. 【自我檢查測試】
   - 使用 Vitest 撰寫至少 10 個涵蓋邊界情境的單元測試（包含：第 4 天 vs 第 5 天高鐵早鳥、愛心陪伴名額上限、連假住宿係數與平日省錢建議、不同身分 AA 分帳加總＋尾差等於總額驗證、週一公休閃避、海象紅燈切雨備、單點替換不重複且即時重算預算、.ics 字串含 VEVENT 與正確日期），執行 `npx vitest run engine/` 與 `npm run typecheck` 確保 100% 通過。
