個人計畫書：架構師

你的定位：你是整個專案的架構師，負責定版雙向資料合約、守護主機推論閘道的安全與穩定、管好 GitHub 自動化部署，並把路線情報員、優惠精算師、介面設計師三條平行產線平滑串接成完整網站。

一、你的專屬主場與邊界

  • 你掌控的目錄：schema/、.github/、根目錄專案設定（package.json、package-lock.json、tsconfig.json、vite.config.ts、專案根目錄 AGENTS.md、CLAUDE.md）、.agents/skills/，以及獨立主機端的閘道服務。
  • 依賴鎖定特權：全專案只有架構師能修改 package.json 與 package-lock.json。你已把全隊需要的套件（leaflet、react-leaflet、zod、lucide-react、vite-plugin-pwa 等）預裝鎖定，防止其他分支因安裝依賴造成版本衝突。
  • 順手幫全隊減壓的認領項：5 區精選景點由 4 人平分人工校對（等路線情報員從 TDX 產出初稿骨架後，你認領 1 個本島區域，例如北北基 補齊公休日與室內雨備標籤即可）。

二、你真正要動腦的地方（AI 不能替你決定）

AI 很會生設定檔，但以下 5 個判斷必須由你拍板：

  1. 雙向合約的「克制度」：schema/trip.ts 決定了整個團隊的溝通成本。你要決定哪些欄位是必填核心（例如 origin、lodgingTier、perIdentitySplit），哪些先留成選填（tips?、aiSummary?），防止大家寫到一半一直膨脹欄位、引發大改。
  2. 三層快取邊界切分：你要跟路線情報員一起劃清楚——哪些資料放 GitHub 靜態 JSON（每日更新）、哪些放 Cloudflare KV（跨節點共用 15 分鐘～3 小時）、哪些留在瀏覽器 localStorage（PWA 離線），才能在 TDX 5 次/分限制下維持流暢。
  3. 主機小模型出錯時的「體面補救」：就算用了 Zod / Pydantic 強型別檢查，4B 小模型有時還是會漏抓出發日期或把離島拼錯。你要設計好「缺項清單回傳格式」，讓前端高亮度提示旅客補點 1 下，而不是整段放棄重來。
  4. 多 AI 協作與 CODEOWNERS 守護：四人各自使用不同 AI（Claude Code、Copilot、Cursor、Antigravity），你需透過 CLAUDE.md、.github/copilot-instructions.md 與 .github/CODEOWNERS，確保每位 AI 都遵守目錄隔離與依賴鎖定。
  5. PR 審查與分支保護管理：透過 GitHub protect-main 分支保護規則（要求 1 位審核、CI 通過、禁直推），審查來自 feat/<角色>-<主題> 的 PR，並把控合併節奏。

四、你的行動步驟

階段 1：建好舞台與雙向合約（開工第 1 天）

  1. 初始化 Vite + React 19 + TypeScript + Tailwind CSS + Vitest 專案骨架，並預裝鎖定 leaflet、react-leaflet、@types/leaflet、zod、lucide-react、vite-plugin-pwa。
  2. 定版 schema/trip.ts（完整納入總計畫書的 TripInput 與 TripPlanResult）並寫好 2 組真實感滿分的 schema/mockTripData.ts（建議：「台北出發澎湖 3 天 2 夜混合團（含海象黃燈與雨備）」、「台中出發台南 2 天 1 夜雙鐵＋好行（含改平日省錢提示）」）。
  3. 設定 GitHub protect-main 分支保護規則（要求 1 位審核、需 Code Owners 審查、需通過 CI 檢查、禁止 force push）。
  4. 部署跨 AI 提示規範檔案：CLAUDE.md、.github/copilot-instructions.md、AGENTS.md、.github/CODEOWNERS 與 .agents/skills/backup/SKILL.md，確保夥伴的各種 AI 都能遵循相同邊界。

階段 2：架設主機「精準雙任務」閘道（與團隊平行推進）

主機不開放無上限自由聊天，只開兩個高穩定 API 端點，並加上 佇列上限 3 人（超過秒回 429）、單一 IP 限流與 Cloudflare Turnstile：

  1. POST /api/parse-input（口語轉條件）：把旅客輸入的一句話（限 500 字內）強制以 format: "json" 解析成 TripInput 欄位；若缺乏必要欄位（如沒寫出發地或天數），回傳已解析部分 ＋ missingFields 清單。
  2. POST /api/summarize（白話導讀）：只吃優惠精算師引擎已經算好的數字與警告，請模型整理成 150 字以內的台灣口語亮點與省錢摘要（嚴禁模型自己猜車次或票價）。

階段 3：協作校對、審查 PR 與發布

  1. 認領並校對 1 區精選景點 JSON（例：北北基），補充公休日與室內備案。
  2. 透過 GitHub PR 流程依序審查並合併 engine/、services/、src/ 的分支（檢查目錄邊界與 CI 綠燈），實測「把主機閘道關掉」時整個網站是否依然能順暢完成排程與分享。
  3. 以 .github/workflows/deploy.yml 完成 GitHub Pages 自動發布。

五、直接貼給架構師 AI 的執行指令

可直接複製給 AI 的執行指令
你是協助「架構師」建立專案基石的系統架構 AI。請幫我處理以下任務，並嚴格遵守專案根目錄的 AGENTS.md 與 .agents/skills/tw-trip-contract/SKILL.md：

1. 【初始化專案骨架與鎖定依賴】
   - 建立 Vite + React 19 + TypeScript (strict: true) + Tailwind CSS + Vitest 專案骨架。
   - 預先安裝 leaflet, react-leaflet, @types/leaflet, zod, lucide-react, vite-plugin-pwa，並將 package.json / package-lock.json 鎖定在 CODEOWNERS 由架構師專屬維護。
   - 建立隔離目錄：schema/、data/、services/、engine/、src/、gateway/。

2. 【定版雙向合約 schema/trip.ts 與 Mock 資料】
   - 依團隊總計畫書完整實作 schema/trip.ts（涵蓋 OriginRegion, RegionCode, LodgingTier, TripInput, CuratedSpot, DayStop, DayPlan, IdentityCostShare, BudgetBreakdown, ReviewWarning, TripPlanResult）。
   - 同時建立對應的 Zod Schema 供執行期驗證使用。
   - 在 schema/mockTripData.ts 撰寫 2 組完整且符合 TripPlanResult 結構的假資料（台北→澎湖 3 天 2 夜混合團含海象雨備、台中→台南 2 天 1 夜含平日省錢提示與分帳明細）。

3. 【主機精準雙任務 FastAPI 閘道 (gateway/main.py)】
   - 僅呼叫本機 127.0.0.1:11434 的 Ollama (qwen3.5:4b)，不暴露 11434 Port。
   - 實作併發 Semaphore=1、等待佇列上限 3 筆（超出立刻回傳 HTTP 429 JSON）。
   - 實作單一 IP 限流、500 字輸入上限，以及僅允許 GitHub Pages 網域的 CORS 設定。
   - 實作兩個端點：
     (a) POST /api/parse-input：強制 JSON 輸出，以 Pydantic 驗證欄位並回傳 parsed 與 missingFields。
     (b) POST /api/summarize：接收引擎算好的確定性數字與警告，輸出 150 字內台灣口語白話導讀（Prompt 明確禁止捏造數字）。

4. 【多 AI 守護與 GitHub 自動化】
   - 建立 .github/CODEOWNERS 明確劃分四人目錄邊界，鎖定 package.json 與 schema/ 變更權限。
   - 建立 CLAUDE.md、.github/copilot-instructions.md 與 .agents/skills/backup/SKILL.md，禁止直推 main、要求 PR 與 pre-push 檢查。
   - 建立 .github/workflows/deploy.yml 支援推送至 main 後自動執行 typecheck、vitest run、build 並部署到 GitHub Pages。
